# pp-desktop

`pp-desktop` is the Tauri 2 shell: it starts `pp-core`, opens one window at the core's loopback origin, and owns the tray, downloads, single-instance focus and open-at-login.

Current ownership and allowed dependencies: [Architecture](../../../docs/architecture.md#crates-and-allowed-edges) and [ADR 0009](../../../docs/adr/0009-keep-crates-and-deepen-modules.md). [ADR 0007](../../../docs/adr/0007-rust-crate-layout.md) is historical dependency evidence only.

## Purpose

- Verifies the staged resources (`ResourceLayout` reads `release.json`) and starts `CoreRuntime`.
- Builds the `main` window and tray, keeps navigation at the exact core origin, and places downloads.
- Runs the installed lifecycle: hide on close, Quit with core shutdown, a second launch focuses the first, a macOS LaunchAgent for open-at-login, the Service logs dialog and the guarded Restart service action (`recovery`, binary only).

## Not responsible for

- Startup, the data directory lock, workers and shutdown: `pp-core`. Headless and Docker runs: `pp-server`. Listeners, sessions and assets: `pp-gateway`. Node supervision and logs: `pp-compat`. SQL: `pp-storage`.
- Domain work over Tauri invoke. The UI talks to the core over authenticated loopback HTTP.

## Interface

The binary is `pp-desktop` (`src/main.rs`). Arguments, parsed by `LaunchArgs::parse`: `--minimized` starts hidden. Debug builds also accept `--dev-stage <dir>`, `--data <dir>`, `--test-exit-seconds <n>` and `--test-recovery-logs`; release builds reject them.

| Item | What it does |
| --- | --- |
| `desktop_data_dir`, `ResourceLayout`, `AllowedOrigin` | Resolve the data directory, verify the stage, check URLs against the core origin. |
| `startup_diagnostic`, `browser_preferences_diagnostic` | Reduce errors to known categories and OS error numbers. |
| `autostart` | `LaunchAgent` (enable, disable), `LaunchArgs`, `MINIMIZED_ARG`, `LABEL`. |
| `browser` | `bootstrap_url` and `opener` for Open in browser. |
| `downloads` | `DownloadPolicy::place` and `DownloadDenied`. |
| `focus` | `FocusServer`, `request`, `owned_by_another_desktop`. |
| `platform` (`linux`, `macos` or `windows`) | What differs by OS: the opener and its reveal arguments, the bundled stage path, whether open-at-login is offered, native dialogs, the stop signal and the focus endpoint. Shared code calls `platform::…` and names no OS. |
| `tray` | Status text and badge (`status`, `badge`, `Tone`), menu IDs, `toggle_open_at_login`. |
| `native_actions` (`desktop_rebuild`) | `SponsorAction` and the `open_sponsor` command. |
| `origin_change` (`desktop_rebuild`) | `OriginBridge`, `user_notice`, `require_fresh_bootstrap`, and the `sync_portable_settings` command. |

Tauri commands: `main.rs` calls `invoke_handler` only with `desktop_rebuild`, registering `open_sponsor` and `sync_portable_settings`. Each also checks the runtime gate, window and webview labels, and origin. Default builds register none.

- `tauri.conf.json`: product name, version, identifier, `frontendDist: "bootstrap"`, no static windows, asset protocol off, and the `main-no-native-commands` capability with no permissions. Code adds the rebuild capabilities at runtime.
- `bootstrap/index.html`: an empty placeholder page for `frontendDist`; the window loads the core URL.
- `icons/icon.ico`: `icons/icon.png` at 16, 24, 32, 48, 64, 128 and 256 px. `tauri-build` requires it on Windows and embeds it in the executable's resources.
- `permissions/autogenerated/`: allow and deny permissions for the two commands, generated by `tauri-build` from the `build.rs` app manifest. Do not edit.
- `gen/schemas/`: schemas `tauri-build` writes during the build; `.gitignore` excludes `/gen/`.

## Effects and flags

- Files: the data directory (default `~/.print-partner`), the focus endpoint (the socket `<data>/.desktop-focus.sock` on Linux and macOS, the named pipe `\\.\pipe\printpartner-focus-<volume serial>-<file index>` of the data directory on Windows), the user's Downloads directory, the stage's `release.json`, and on macOS `~/Library/LaunchAgents/com.poitee.printpartner.plist`.
- Child processes: `xdg-open`, `/usr/bin/open` or `rundll32` for browser handoff and the log folder. The Sponsor launcher has a five-second timeout.
- One multi-thread Tokio runtime, shared with Tauri. Native dialogs use GTK on Linux and `rfd` elsewhere.
- Stop signals: Ctrl+C everywhere, SIGTERM on Linux and macOS, Ctrl+Break and a console close on Windows. Each starts the same core shutdown.
- Env: with `desktop_rebuild`, `PP_DESKTOP_REBUILD` (through `pp_core::DesktopRebuild::from_env`) and, when it is on, `PP_PORTABLE_DIR`, `APPDATA`, `LOCALAPPDATA` and `XDG_*_HOME` (through `pp_core::layout::LayoutEnvironment`). With `desktop-e2e`, `PP_DESKTOP_E2E_MARKER`.
- Build: `pp-compat`'s build script embeds `PP_DESKTOP_RELEASE_MANIFEST`, defaulting to `rust/bundle-manifest.json`. The build fails when neither exists.
- Windows MSVC builds link the Visual C++ runtime dynamically: `build.rs` turns off tauri-build's static runtime, whose stub `msvcrt.lib` on the link search path broke every workspace doctest link. A Windows installer must ship the VC++ redistributable or build the whole binary with `+crt-static`.

Features (both default off):

- `desktop_rebuild`: enables `pp-core/desktop_rebuild`, the two gated modules and commands, and the portable data layout. It also needs `PP_DESKTOP_REBUILD=1` or `true` at runtime.
- `desktop-e2e`: adds the `tauri-plugin-wdio-webdriver` plugin. A release build with it fails to compile.

## Single-instance focus

A second launch that the data directory lock refuses asks the owner to show its window, then exits. The owner listens only while it holds the lock, and answers `focused` only to a request that names the device and file number of its own data directory.

- Linux and macOS: a Unix socket in the 0700 data directory, mode 0600. The owner answers only a peer with the directory owner's uid. A leftover socket is replaced; any other file at that path is left alone and focus stays off.
- Windows: a named pipe whose name carries the data directory's volume serial number and file index. The pipe has a protected DACL that grants only the current user, rejects remote clients, and is created with `FILE_FLAG_FIRST_PIPE_INSTANCE`, so a pipe another process already holds under that name turns focus off instead of being shared. The client asks only a pipe whose DACL grants this user alone (`CurrentUser::owns_privately` from `pp-os`), so it never writes to a pipe someone else planted. There is no TCP fallback.

Focus is best effort: any failure keeps the normal startup error.

Every test runs on Linux, macOS and Windows except the focus endpoint tests: `unix::tests` checks the socket's mode and stale-socket replacement, and `windows::tests` checks the pipe's private DACL and refuses a planted pipe. ## Run the native development app

Install Rust 1.99.0 and Node 24.21.0. Install the workspace dependencies with `npm --prefix web ci`. From the repository root, launch with:

```sh
PP_DEV_NODE=/absolute/path/to/node bash rust/scripts/desktop-dev.sh
```

The command builds the trusted React assets and real compatibility server, creates a new stage, embeds its measured inventory, and starts one native window with isolated temporary data. Set `PP_DEV_DATA` to an existing development directory to keep that directory across runs. Set `PP_DEV_STAGE` to a new directory to retain its staged files. The stage command refuses to overwrite an existing directory.

Closing the window hides it while core continues. The tray has Show, Open in browser, service status, View logs, Reveal log folder, a guarded Restart service action, Open data folder, and Quit. Quit and supported OS exits wait for the consuming core shutdown before the process returns. Navigation stays at the exact core origin and popups are denied. The enabled rebuild shell can show a plain notice when a saved port was busy, restore the three portable browser preferences on that new address, and open the Sponsor action. Both need `desktop_rebuild` at build time and `PP_DESKTOP_REBUILD` set to `1` or `true`. Downloads are covered under "Verify downloads" below. Other external handoff flows still need a validated native UX.

View logs reads a bounded recent history and removes unknown events and fields before display. It remains available when the compatibility service stops. Restart service admits one request per crash-guard episode. Local crash records retain only known failure categories and numeric exit codes or signals. They contain no backend messages, paths, credentials, or panic payloads.

Native offline backup restore and opt-in Rust Sentry delivery remain unavailable. The tray does not call the live restore route. A safe restore must retain the original storage lease and stop all writers before replacing files.

In a debug build, add `--test-recovery-logs --test-exit-seconds 20` to the native launch command to open the same Service logs dialog for a repeatable UI probe. The timed shutdown still completes while the dialog is open. Release builds reject both probe arguments.

On the nonprivileged Linux development host, set `PP_NATIVE_SYSROOT` to the already extracted GTK/WebKit SDK. `native-sdk.sh` reads that SDK without changing it. Other hosts use their target-native development packages. This SDK does not produce a portable Linux distribution image.

## Create an unsigned target-native stage

Build the desktop assets first, then run:

```sh
python3 rust/scripts/stage-desktop.py --web web --node /absolute/path/to/node --output /new/stage/path --commit "$(git rev-parse HEAD)"
```

The stage copies the real production dependencies, including optional production packages marked `devOptional` by npm, and checks their native SQLite addon with the staged Node. It stages an npm workspace link only when the stage already holds the link's target, so workspaces the desktop bundle does not ship, such as `apps/ui`, leave no dangling link; the final JSON lists them under `skipped_workspace_links`. Native architecture must match the builder. On macOS, the stage uses `/usr/bin/lipo` to select the verified Node architecture from universal addons before moving them into Frameworks or measuring dependencies. Already-thin target addons keep their exact bytes. Missing or invalid target slices stop staging; selected candidates replace staged files only after validation. This normalization precedes nested signing and measurement. The manifest covers build content, Node, complete dependency files, and exact symlink targets. Rust checks dependencies again before each compatibility process start. Generated inventories stay outside source control. The inventory records missing resolver roots inside the package so adding a nearer node_modules directory is rejected. The measured `desktop-resolution.js` preload rejects resolved or loaded files outside the package root, including ancestor and symlink ancestor dependencies; `rust/tests/enforced_launch.py` verifies these boundaries. The global search flag alone does not confine resolution.

Release builds reject `--dev-stage`, `--data`, and the timed native probe argument. Packaged resource lookup has no global Node fallback. A package needs the actual staged resources and a Rust binary compiled with that stage's `PP_DESKTOP_RELEASE_MANIFEST`.

The manifest builder adds deterministic `.gz` companions for HTML, JavaScript, CSS, SVG, JSON, source maps, Wasm, and text files. It excludes `desktop-build.json`. Generation re-encodes valid existing companions into canonical bytes and retains the originals' read and write permissions. Both representations enter the existing embedded SHA-256 inventory.

Missing `index.html`, symlinks, orphan gzip files, corrupt gzip files, and decoded content that differs from its original stop the build. The builder uses the resolved web directory as its trusted boundary and rejects asset-root or intermediate symlinks below it before writing. Standalone commands trust the asset root's parent by default, including platform aliases such as macOS temporary directories. Set `--boundary` to check intermediate paths below a wider trusted parent. To validate content and containment without writing files, run `python3 rust/scripts/precompress-spa.py /path/to/web/apps/web/dist --boundary /path/to/web --validate`. Rebuild the frontend into a clean `dist` directory after changing assets.

Compression and validation use 64 KiB buffers. The macOS build selector treats the compression script as a native packaging input. This prerequisite adds no routes or UI and needs no `desktop_rebuild` opt-in. The gateway still serves original files. Content negotiation, Brotli, embedded asset bytes, and signed native release receipts remain open under GRE-343.

The unsigned bundle helper expects pinned `cargo-tauri` 2.12.1 installed on macOS:

```sh
PP_DESKTOP_STAGE=/absolute/stage/path bash rust/scripts/desktop-bundle.sh
```

It validates the completed measured stage, invokes Tauri with `--no-sign --no-binary-patching`, and refuses other hosts. The generated macOS configuration leaves runtime resources to `assemble-macos-resources.py`; Tauri still copies the measured Node and Frameworks files and creates the icon, plist and main executable.

The assembly helper requires a fresh unsigned app with matching product identity and native bytes. It copies the complete runtime tree with relative aliases intact, checks the private candidate against the unchanged manifest, and atomically publishes it to the absent `Contents/Resources/desktop-runtime` destination. Missing or altered source files, escaping aliases, unrelated resources, an existing runtime destination and failed copies stop assembly.

This helper has not established a signed release. macOS nested code must be signed before generating its final inventory and compiling Rust. Bundling must preserve those bytes. Sign the outer app afterward, compare nested hashes again, and verify notarization, stapling, installation, and native launch separately. A Linux native process receipt proves neither macOS behavior nor successful UI rendering.

## Check unsigned macOS bundles in CI

The `Native macOS bundle` workflow builds separate arm64 and x86_64 apps on `macos-26` and `macos-26-intel`. Each job installs Rust 1.99.0, Node 24.21.0 ABI 137, and Tauri CLI 2.12.1. It installs the locked npm tree on that architecture, builds the desktop React assets, stages production dependencies, and calls the existing unsigned bundle helper once. Native npm builds inherit `MACOSX_DEPLOYMENT_TARGET=13.5`. Cargo fetch uses the committed lockfile; the app build runs offline and fails if either lockfile changes.

To inspect a completed app on macOS, keep the exact manifest used to compile it, then run:

```sh
python3 rust/scripts/check-macos-bundle.py \
  --app '/path/Print Partner.app' \
  --manifest /path/bundle-manifest.json \
  --arch arm64 \
  --receipt /path/bundle-verifier.json
```

Use `--arch x86_64` for the Intel app. The checker requires the installed `Info.plist` floor to equal 13.5. It compares installed Node, frontend, backend, metadata, complete dependency files, resolver roots, and relative workspace aliases with the frozen inventory. It inspects every app-owned Mach-O with `file`, `lipo`, and `otool`. Every binary must match the job architecture and target macOS 13.5 or earlier. External native dependencies fail verification unless they are system libraries under `/usr/lib` or `/System/Library`. Receipts list those system libraries; the app does not bundle them. Dependency traversal keeps the loading executable and image chain separate for each process. Node addons use `printpartner-node` and the rpaths of their own loader chain. They cannot borrow the Tauri executable's rpaths. Dylibs inherit rpaths from their actual chain, and `@loader_path` resolves relative to the image that declares it. Receipts retain those executable contexts and resolved dependencies.

The workflow copies the app to a separate path with a space in its directory name and repeats all checks against that installed tree. Each verifier runs the installed Node, checks a real SQLite query, and paints and encodes a Canvas image through the locked `@napi-rs/canvas` addon. It checks the pixel values, PNG signature, and canonical loaded addon paths against both installed aliases. This probe uses the measured resolution preload and confined arguments. It does not establish that the current shipping process passes those arguments; that enforcement has a separate review gate.

Each architecture uploads an unsigned app archive when one exists, the exact compile-time manifest, the stage manifest after bundling, generated bundle configuration, tool versions, build logs, and original and relocated verifier receipts. Available evidence uploads even when a check fails. Parser and inventory negative controls also run on Linux with `python3 rust/scripts/check-macos-bundle.py --self-test`. Linux checks cannot establish Mach-O, Info.plist, or bundle behavior.

These jobs cover unsigned assembly and installed resource checks. Native launch and rendered React verification remain separate gates. The existing timed lifecycle probe needs a debug build and Linux-specific isolation, so these release jobs do not run it. Signing still follows the required sequence: finish nested signing, measure nested bytes, compile Rust with that manifest, assemble without signing or binary patching, then sign the outer app and compare the nested hashes again. This workflow supplies no signing credentials and creates no release, notarization submission, or deployment. Node remains temporary compatibility code.

The `Desktop runtime` workflow runs on Ubuntu 24.04 for Rust and desktop dependency changes. It generates a current-head manifest after the real desktop asset build, builds `pp-server`, runs the eight real `runtime_m0` tests, backend units and Clippy, boundary and format checks, authenticated workflow and cleanup proofs, and gateway effects, product, and streaming probes. Crate selection excludes `pp-desktop` from Linux compilation. The test fixtures require `/usr/bin/node`, so the disposable runner points that path at the pinned setup-node runtime before measurement. Logs and exact manifest bytes upload on failure. This workflow needs the gateway test files from the reviewed integration stack; the Native-only base does not contain them.

## Verify the native Sponsor action

The native Sponsor action supports Linux and macOS only. Windows support is deferred. Build with `--features desktop_rebuild` and enable the runtime with `PP_DESKTOP_REBUILD=1` or `true`. Both gates and a supported platform are required. Other platforms receive no Sponsor capability or bridge. The shell injects a nullary Sponsor bridge into its main document at the exact core HTTP origin. Ordinary web sessions retain the browser popup behavior. A native error displays a toast with the public Sponsors address and does not retry through a popup.

The action opens only `https://github.com/sponsors/poitee` in the OS browser. JavaScript cannot supply a destination. Its remote capability grants only `allow-open-sponsor` to the `main` webview at the captured loopback host and port. The command also checks the captured runtime gate, current origin, window label, and webview label. Local application URLs and general shell, filesystem, opener, and window commands receive no permission. The browser launcher has a five-second timeout and kills its child on cancellation. A timeout cannot prove the browser failed to open. Linux `xdg-open` may remain running until the browser exits, even after opening the page. The toast therefore reports that browser opening could not be confirmed.

The bridge does not prove a user gesture or distinguish same-origin child frames that can access their parent. Tauri IPC source attribution differs by platform. Linux postMessage IPC uses the webview's current URL rather than the requesting frame's URL. The guarantee is the exact bound main webview origin and Tauri's invoke-key boundary, not independent authentication of every frame.

Run the unit checks from the repository root:

```sh
PP_DESKTOP_RELEASE_MANIFEST=/absolute/path/to/stage/bundle-manifest.json \
  cargo test --locked --manifest-path rust/Cargo.toml -p pp-desktop --features desktop_rebuild --lib
npm --prefix web run test -w @print-partner/web -- src/lib/supportLinks.test.ts
```

On Linux with WebKitWebDriver and Xvfb available, run the native click and denial verifier against a freshly built binary and stage:

```sh
dbus-run-session -- xvfb-run -a python3 rust/tests/native_sponsor.py \
  --binary rust/target/debug/pp-desktop \
  --stage /absolute/path/to/stage --output /tmp/gre353-sponsor-proof
```

The verifier records the browser handoff through an isolated `xdg-open` shim, so verification does not launch an external browser.

## Verify downloads

Every build of the shell handles webview downloads itself; no feature or runtime gate is involved. The `main` webview may download only from the exact core origin, or from a `blob:` URL that origin created. Each file goes to the user's Downloads directory. Only the last component of the webview's proposed path is kept, and characters or names that Windows, macOS or Linux treat specially are removed. A name that any existing path uses, including a dangling symlink, or that an earlier download in this session took, gets the next free ` (n)` suffix. Without a Downloads directory, the shell refuses the download. Logs record only the URL scheme and the outcome.

The check sees the request URL, so a same-origin response that redirects elsewhere is not checked again. The shell does not restrict file types or check file contents. On Linux, WebKitGTK sends an `<a download>` click through the navigation check first. That check rejects `blob:` documents, so blob downloads save nothing there.

Run the unit checks, then the native verifier on Linux with WebKitWebDriver and Xvfb:

```sh
PP_DESKTOP_RELEASE_MANIFEST=/absolute/path/to/stage/bundle-manifest.json \
  cargo test --locked --manifest-path rust/Cargo.toml -p pp-desktop --lib downloads
dbus-run-session -- xvfb-run -a python3 rust/tests/native_downloads.py \
  --binary rust/target/debug/pp-desktop \
  --stage /absolute/path/to/stage --output /tmp/gre353-downloads-proof
```

The verifier plants a dangling `escape.json` symlink in an isolated Downloads directory. It then requires two same-origin downloads to land as `escape (1).json` and `escape (2).json`, the symlink target to stay absent, and `data:` and `blob:` clicks to save nothing.
